## 现在整条链路能跑通什么

1. 买家注册 / 登录（密码至少 8 位，必须同时有字母和数字，例如 `buyer123`）
2. 浏览首页、分类、商品详情，加入购物车
3. 选地址后结算下单
4. 支付页可以打开**支付宝沙箱收银台**
5. 本地联调点 **「完成本地支付」**，订单会变成已支付
6. 后台能看订单、改分类、上架商品

后台账号：`admin` / `admin123`  
商家端账号：`merchant` / `merchant123`（http://localhost:5175）  
商城：先自己注册一个买家。

## 今天修了哪些坑（按发生顺序）

| 现象 | 原因 | 怎么处理的 |
|------|------|------------|
| 结账 500：`try to proceed invocation error` | 订单和库存各开了一层 Seata 全局事务，嵌套失败 | 库存只保留本地事务 |
| 结账 500：`Failed to fetch schema of order_info` | 订单是分表（`order_info_0~7`），Seata 去查逻辑表拿不到主键 | 订单服务关掉 Seata，下单改本地事务；锁库存失败会回滚订单 |
| `receiver_name doesn't have a default value` | 只传了地址 ID，再去查地址失败，收货人是空的 | 结账时带上完整地址；查不到就用默认地址；仍缺则直接提示 |
| 超时关单失败：`Can not update sharding value` | `updateById` 把分片键 `user_id` 一起改了 | 只更新状态等字段，WHERE 带上 `user_id` |
| 支付页「订单不存在」 | 雪花 ID 18 位，浏览器 `Number()` 丢精度 | 按 `orderNo` 查单；Long ID 改成字符串返回 |
| 支付宝网关 POST 404 | 沙箱电脑网站支付不吃 POST | 改成 GET 跳转收银台 |
| 沙箱页一堆红字 | 支付宝自己的埋点 / HTTP 脚本，不是我们的 bug | 新标签打开沙箱；本地用「完成本地支付」点亮订单 |

另外：商城分类改成了级联下拉；后台换了深色侧栏、工作台卡片、分类/商品下拉，列表页统一成卡片样式。
